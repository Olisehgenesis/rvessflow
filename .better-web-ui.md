## Design Context

### Users
Everyday savers on a phone, often between other tasks. The first persona is someone like Alex who wants a named goal, a deposit, and a clear date. A second job is sending money to someone else on a schedule, or locking an amount until a date. Groups are small circles (friends, a family pot), not trading desks. The protocol admin is a separate person and is not the default screen.

### Brand Personality
Calm, plain-spoken, trustworthy. Three words: clear, warm, steady. The product should feel like money that is already arranged, not a market to watch. Copy talks about goals, holds, and dates. It does not hype yield.

### Aesthetic Direction
Light surfaces, deep green actions, soft cool paper behind the cards. Follow the attached phone flows: splash, home, create goal (saving / flow / expense), flow details, lock, group rotation, settings, and the everyday-saver path from suggestion to progress. Rounded cards, one primary green button per screen, bottom navigation (Home, Goals, Vaults, Groups, More). Numbers are the hierarchy. Illustrations are original and used at empty states, the splash, and the goal-created moment. Avoid a generic purple dashboard, dark crypto chrome, fake phone bezels around the whole site, and dollar amounts that are not on chain.

Desktop (viewport `lg`, 1024px and up) uses the RvessFlow reference: warm off-white paper (`#F3F6EE`), near-black type, lime `#D6F34A` as the signature action, Manrope for desktop headings and Inter for body, rounded cards with a hairline border. Stream uses the existing lavender, lock and save use the existing sprout art. Android and narrow screens keep the unprefixed classes, bottom navigation, and current assets. Do not restyle those to match desktop.

### Implementation Defaults
Next.js App Router at the repo root, Tailwind, shadcn/ui on Radix. Forms use React state with explicit submit (the actions are chain transactions, not auto-save). No table library and no virtualization; lists are short. Chain access is viem on the server for the four funded Base Sepolia accounts, plus public reads. Keys stay on disk and never ship to the browser. The Foundry project lives in `contracts/`.

### Design Principles
- One obvious next step per screen. A goal screen asks for a name, an amount, and a date, then one button.
- Show chain state, including zeros and empty lists. An empty home explains the next deposit instead of inventing a balance.
- Hierarchy comes from the amount and the goal name. Color marks status (holding, streaming, locked) and the primary action.
- Protocol limits stay visible in plain language: a hold does not stream, a lock penalty is fixed when the lock is created, a group needs its members before it starts.
- Admin controls appear only for the protocol admin. Everyone else sees the live setting, not a switch that cannot work.
- Desktop presentation is a layer on top of the phone UI. New desktop styling uses `lg:` or a `hidden lg:` sibling. Unprefixed classes that Android renders stay put.
